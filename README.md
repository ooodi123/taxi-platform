# Платформа такси для таксопарков — бэкенд (этап 1)

White-label платформа: один сервер обслуживает много таксопарков. У каждого таксопарка свои тарифы, водители, диспетчеры и заказы, и они не видят данные друг друга.

**Этап 1 (готово):** ядро — таксопарки, тарифы, водители, заказы, расчёт цены, автоматический подбор ближайшей машины, живые обновления через сокеты.
**Этап 2 (готово):** Telegram-бот таксопарка, вход через Telegram, Mini App пассажира с картой, поиск адресов, уведомления в чат.
**Этап 3 (готово):** Mini App водителя: смена, заказы со звуком и таймером, статусы поездки, навигатор, заработок за день.
**Этап 4 (готово):** веб-диспетчерская: живая карта, лента заказов, заказ по телефону, ручное назначение, водители, тарифы, настройки и бот.
**Этап 5–6 (готово):** брендинг для каждого таксопарка (свой бот, название, цвет), запуск на сервере с HTTPS, ночные бэкапы, скрипты обслуживания, демо-режим с виртуальными водителями.

👉 **Как запустить на сервере и показать клиентам — [DEPLOY.md](DEPLOY.md).**

## Как это работает

```
Пассажир ──► POST /api/orders ──► заказ «Ищем машину»
                                     │
            Redis GEO: ближайшие свободные водители в радиусе 2 → 5 → 10 км
                                     │
                     предложение ближайшему (15 сек на ответ)
                  ┌──────────────────┼───────────────────┐
              принял            отказался          не ответил
                  │                  └──── следующему ───┘
                  ▼
   «Водитель едет» → «Водитель на месте» → «В пути» → «Завершён»
```

- Заказ никто не взял за 5 минут — статус «Машина не найдена».
- Водитель отказался от принятого заказа до посадки — заказ снова ищет машину, этому водителю больше не предлагается.
- Диспетчер может принять заказ по телефону и назначить водителя вручную.
- Пассажир видит машину на карте в реальном времени, диспетчер видит всех водителей.
- Состояние подбора хранится в базе, поэтому перезапуск сервера ничего не ломает.

**Стек:** Node.js 22, TypeScript, NestJS, PostgreSQL 16, Redis 7, Socket.IO.

## Запуск на сервере (Docker)

Нужен VPS с Ubuntu, Docker и Docker Compose.

```bash
# 1. Залейте папку taxi-platform на сервер и зайдите в неё (сборка идёт из корня — нужны backend/ и webapp/)
cd taxi-platform

# 2. Настройки
cp .env.example .env
nano .env        # заполните пароли и секреты (openssl rand -hex 32)

# 3. Запуск
docker compose up -d --build

# 4. Проверка
curl http://localhost:3000/api/health       # {"ok":true,...}
docker compose logs -f api                  # логи
```

API слушает только `127.0.0.1:3000`. Наружу его нужно открыть через nginx или Caddy с HTTPS (Telegram Mini App работает только по HTTPS). Это сделаем на этапе 6.

### Демо-режим

Пока нет Mini App, пассажиры и водители входят через тестовый вход `/api/auth/dev/token`. Для этого в `.env`:

```
NODE_ENV=development
DEV_AUTH=true
```

и загрузите демо-данные:

```bash
docker compose exec api node dist/scripts/seed.js
```

Появится таксопарк «Демо Такси» (slug `demo`): владелец `demo / demo12345`, диспетчер `demo-dispatcher / dispatch123`, водители с Telegram ID 1001, 1002, 1003.

⚠️ С `DEV_AUTH=true` любой может войти под любым водителем. Только для демо, не для реальных клиентов. В режиме `NODE_ENV=production` сервер с таким флагом не запустится.

## Telegram-бот и Mini App пассажира (этап 2)

### Как пассажир заказывает такси

1. Находит бота таксопарка в Telegram и нажимает «Старт» (или кнопку меню «Такси»).
2. Открывается Mini App: карта, пин стоит там, где пассажир. Двигая карту, он уточняет место подачи.
3. Выбирает, куда ехать: поиском по адресу или пином на карте.
4. Видит цены по всем тарифам, выбирает, пишет комментарий водителю и нажимает «Заказать».
5. Ждёт машину: видит номер, марку, цвет, водителя, машину на карте, время подъезда, может позвонить.
6. Бот дублирует важное в чат: «Машина найдена», «Водитель на месте», «Поездка завершена, 420 ₽».

### Подключение бота к таксопарку

Нужен публичный адрес с HTTPS (`PUBLIC_URL` в `.env`): Telegram не работает с ботами по http.

1. Таксопарк создаёт бота в [@BotFather](https://t.me/BotFather) (`/newbot`) и присылает токен.
2. Подключаете (вы как супер-админ или владелец таксопарка сам):

```bash
# супер-админ
curl -X PUT https://ваш-домен/api/admin/tenants/<id таксопарка>/bot \
  -H "X-Super-Admin-Key: $SUPER_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"botToken": "123456:ABC..."}'

# или владелец таксопарка своим токеном входа
curl -X PUT https://ваш-домен/api/bot -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" -d '{"botToken": "123456:ABC..."}'
```

Сервер сам проверит токен, настроит webhook, кнопку меню «Такси» и команду /start. В ответе — ссылка на бота.

3. Брендинг и город по умолчанию:

```bash
curl -X PATCH https://ваш-домен/api/admin/tenants/<id> -H "X-Super-Admin-Key: $SUPER_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"branding": {"appName": "Такси Люкс", "primaryColor": "#2E7D32"}, "settings": {"center": [47.0105, 28.8638]}}'
```

Фирменный цвет красит кнопки, пин и выбранный тариф; светлая или тёмная тема берётся из Telegram пассажира.

### Проверить Mini App в браузере без Telegram

При `DEV_AUTH=true` откройте: `http://localhost:3000/app/?t=demo&dev=7001`, где `7001` — любой тестовый Telegram ID. Вход без проверки подписи, только для разработки.

### Карта и поиск адресов

- **Карта**: тайлы OpenStreetMap. Для старта подходят, но у публичного сервера тайлов есть ограничения нагрузки. Когда пойдут реальные заказы, подключите платный сервис тайлов (MapTiler, Stadia и т. п.) и пропишите адрес в `webapp/index.html` перед `app.js`: `<script>window.TAXI_TILES = 'https://.../{z}/{x}/{y}.png?key=...'</script>`.
- **Поиск адресов**: идёт через сервер (`/api/geo/search`, `/api/geo/reverse`), ответы кэшируются в Redis на неделю. По умолчанию — публичный Nominatim, около 1 запроса в секунду. Под нагрузкой: свой Nominatim или Photon, адрес в `GEOCODER_URL`. В `GEOCODER_USER_AGENT` укажите свой контакт, этого требуют правила Nominatim.

### Новые API этапа 2

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| POST | /auth/telegram | все | вход из Mini App `{tenantSlug, initData, role}` |
| PATCH | /auth/me | пассажир | имя и телефон (телефон увидит водитель) |
| GET / PUT / DELETE | /bot | владелец | статус / подключить / отключить бота |
| GET / PUT / DELETE | /admin/tenants/:id/bot | супер-админ | то же для любого таксопарка |
| POST | /telegram/webhook/:tenantId | Telegram | входящие сообщения бота (защищено секретом) |
| GET | /geo/search?q=&lat=&lng= | все | поиск адреса |
| GET | /geo/reverse?lat=&lng= | все | адрес по точке |

Mini App лежит в папке `webapp/` и раздаётся сервером по адресу `/app/`. Сборка не нужна, это обычные HTML, CSS и JavaScript.

## Mini App водителя (этап 3)

### Как водитель работает

1. Диспетчер добавляет водителя с его Telegram ID (`POST /api/drivers`, поле `telegramId`). Свой ID водитель узнаёт, написав боту `/driver`.
2. Водитель открывает бота: под «Заказать такси» у него есть кнопка «Я водитель» (и команда `/driver`).
3. Нажимает «Выйти на линию». Приложение берёт геопозицию и каждые 5 секунд отправляет её на сервер.
4. Приходит заказ: звук, вибрация, цена крупно, расстояние до подачи, маршрут, комментарий и убывающая полоса таймера (15 секунд). «Принять» или «Пропустить».
5. Дальше по шагам: «Я на месте» → «Пассажир сел, начать поездку» → «Завершить поездку». На каждом шаге есть кнопка навигатора (Яндекс Карты, 2ГИС, Google Maps) и звонка пассажиру.
6. После поездки — сумма, которую нужно получить с пассажира, и заработок за день.

### Важное ограничение Telegram

Пока приложение водителя открыто, всё работает в реальном времени. Если водитель свернёт Telegram, приложение «засыпает»: координаты перестают отправляться, и через 60 секунд (`DRIVER_LOCATION_TTL_SEC`) сервер перестаёт предлагать ему заказы. Чтобы водитель не пропустил заказ, когда приложение закрыто, бот присылает в чат сообщение с ценой и адресом и кнопкой «Открыть заказ».

Для постоянной работы в фоне нужно нативное приложение водителя (React Native) — сервер к нему уже готов, API то же самое.

### Проверить в браузере без Telegram

`http://localhost:3000/app/driver/?t=demo&dev=1001` (при `DEV_AUTH=true`, после `seed`; 1001–1003 — водители демо-таксопарка). Вторая вкладка `http://localhost:3000/app/?t=demo&dev=7001` — пассажир. Закажите такси и примите заказ водителем.

### Новые API этапа 3

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| GET | /driver/stats | водитель | поездки, выручка и пробег за сегодня (часовой пояс — `settings.timezone` таксопарка, по умолчанию Europe/Moscow) |

## Диспетчерская (этап 4)

Адрес: `https://ваш-домен/app/dispatch/`. Вход — логином и паролем владельца или диспетчера таксопарка (демо: `demo / demo12345`).

**Заказы.** Слева лента: сверху заказы, которые ищут машину (полоса показывает, сколько из 5 минут поиска прошло; после 2 минут заказ подсвечивается красным — пора назначить вручную), ниже остальные активные. Вкладка «Все за сегодня» — история дня. В центре карта: машины (зелёные — свободны, синие — на заказе, бледные — давно не присылали координаты) и мигающие точки подачи заказов в поиске. Справа карточка заказа: маршрут, цена, клиент, водитель, история событий, ручное назначение ближайшего свободного водителя и отмена с причиной.

**Новый заказ по телефону.** Телефон клиента, адреса «откуда» и «куда» (поиском или кликом по карте), выбор тарифа с ценой, комментарий водителю. После создания система сразу ищет машину, как для заказа из приложения.

**Водители.** Таблица со статусами, поиск, добавление и правка: машина, госномер, Telegram ID, какие тарифы может возить, отключение.

**Тарифы.** Подача, км, минута, минимум, округление и пример цены поездки на 5 км / 15 минут. Менять может только владелец.

**Настройки** (владелец). Название, название в приложении, фирменный цвет, часовой пояс, центр карты; подключение Telegram-бота по токену; диспетчеры — добавить или отключить.

Новый заказ из приложения сопровождается коротким звуком (после первого клика на странице — так требует браузер).

### Новые API этапа 4

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| GET | /orders?scope=active / today | все | активные заказы / созданные сегодня |
| GET | /tenant | владелец, диспетчер | настройки своего таксопарка |
| PATCH | /tenant | владелец | `name`, `appName`, `primaryColor`, `center: [lat, lng]`, `timezone` |

`GET /auth/me` для сотрудников теперь возвращает и данные таксопарка.

## API

Все запросы — `/api/...`, JSON. Авторизация: заголовок `Authorization: Bearer <токен>`.

### Роли

| Роль | Кто | Как получает доступ |
|---|---|---|
| superadmin | вы, владелец платформы | заголовок `X-Super-Admin-Key` |
| owner | владелец таксопарка | `POST /auth/login` |
| dispatcher | диспетчер | `POST /auth/login` |
| driver | водитель | пока `POST /auth/dev/token`, на этапе 2 — Telegram |
| passenger | пассажир | пока `POST /auth/dev/token`, на этапе 2 — Telegram |

### Супер-админ: подключение нового таксопарка

```bash
curl -X POST http://localhost:3000/api/admin/tenants \
  -H "X-Super-Admin-Key: $SUPER_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"name": "Такси Люкс", "slug": "lux"}'
```

В ответе логин и пароль владельца таксопарка. Пароль показывается один раз.

| Метод | Путь | Что делает |
|---|---|---|
| POST | /admin/tenants | создать таксопарк (+ тариф «Эконом» и владелец) |
| GET | /admin/tenants | все таксопарки со статистикой |
| PATCH | /admin/tenants/:id | изменить, отключить (`isActive: false`), брендинг |

### Владелец и диспетчер

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| POST | /auth/login | все сотрудники | вход `{login, password}` |
| GET | /tariffs | все | тарифы |
| POST / PATCH | /tariffs, /tariffs/:id | владелец | тариф: `baseFare` подача, `perKm`, `perMin`, `minFare`, `roundTo` |
| GET / POST | /staff | владелец | диспетчеры |
| GET | /drivers | владелец, диспетчер | водители (`?status=online`) |
| GET | /drivers/live | владелец, диспетчер | водители на линии с координатами — для карты |
| POST / PATCH | /drivers, /drivers/:id | владелец, диспетчер | добавить / изменить водителя, `tariffCodes`, отключить |
| POST | /orders | владелец, диспетчер | заказ по телефону (`customerPhone` обязателен) |
| GET | /orders | все | список (`?status=&limit=&offset=`) |
| GET | /orders/:id/events | владелец, диспетчер | история событий заказа |
| POST | /orders/:id/assign | владелец, диспетчер | назначить водителя вручную `{driverId}` |
| POST | /orders/:id/cancel | все | отменить `{reason}` |

### Пассажир

| Метод | Путь | Что делает |
|---|---|---|
| GET | /tenants/:slug | название и брендинг таксопарка (без авторизации) |
| POST | /orders/estimate | цены по всем тарифам `{pickup, dropoff}` |
| POST | /orders | заказать `{pickup: {lat, lng, address}, dropoff, tariffId, comment}` |
| GET | /orders/current | текущий заказ |
| GET | /orders | история поездок |
| POST | /orders/:id/cancel | отменить (до начала поездки) |

### Водитель

| Метод | Путь | Что делает |
|---|---|---|
| GET | /driver/me | профиль и статус |
| POST | /driver/shift/start | выйти на линию `{location: {lat, lng}}` |
| POST | /driver/shift/end | уйти с линии |
| POST | /driver/location | координаты `{lat, lng}` (каждые 3–10 сек) |
| GET | /orders/current | текущий заказ или предложение |
| POST | /orders/:id/accept, /decline | принять / отказаться от предложения |
| POST | /orders/:id/arrived, /start, /complete | на месте → поездка → завершить |
| POST | /orders/:id/cancel | отказаться от принятого заказа до посадки |

### Сокеты (живые обновления)

```js
const socket = io('https://ваш-домен', { auth: { token } });
socket.on('order:updated', (order) => { /* карточка заказа изменилась */ });
socket.on('order:offer', ({ order, expiresAt, distanceToPickupM }) => { /* водителю: новый заказ */ });
socket.on('order:offer_cancelled', ({ orderId }) => { /* предложение снято */ });
socket.on('driver:location', ({ lat, lng }) => { /* машина на карте */ });
socket.emit('driver:location', { lat, lng }); // водитель шлёт координаты
```

## Настройки подбора (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| OFFER_TIMEOUT_SEC | 15 | сколько секунд водитель думает над заказом |
| SEARCH_RADII_KM | 2,5,10 | радиусы поиска по очереди |
| ORDER_SEARCH_TIMEOUT_SEC | 300 | через сколько поиск прекращается |
| DRIVER_LOCATION_TTL_SEC | 60 | водитель без свежих координат не получает заказы |
| OSRM_URL | пусто | свой сервер маршрутов OSRM. Без него расстояние = по прямой × 1.35 |
